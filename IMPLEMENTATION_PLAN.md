# План реализации backend-проекта

1. **Подготовить каркас проекта и границы домена**  
Определить модули: документы (invoice/borderou), нумерация, платежи, отчёты, экспорт, PDF.

2. **Спроектировать и внести БД-схему (1-й коммит)**  
Добавить таблицы документов, счётчиков, платежей и связи. Заложить уникальность номера документа и индексы для отчётов.

3. **Реализовать безопасную нумерацию без дыр (2-й коммит)**  
Сделать atomic numbering в транзакции с блокировкой записи счётчика, чтобы параллельная генерация не дублировала номера.

4. **Сделать генерацию invoice на delivered order (3-й коммит)**  
Endpoint/use-case: по доставленному заказу создать invoice, присвоить серию+номер, сохранить.

5. **Сделать PDF для invoice и borderou по route (4-й коммит)**  
Генерация PDF-документов и выдача через endpoint (download/stream).

6. **Добавить sold client и aging buckets (5-й коммит)**  
Рассчитать `facturat - încasat`, разложить долг по `0-30`, `31-60`, `>60` дней, отдать в отчёте.

7. **Добавить экспорт CSV/XLSX по интервалу дат (6-й коммит)**  
Экспортировать отчётные данные за `from/to` в двух форматах.

8. **Закрыть ключевой acceptance test (в последнем коммите)**  
Тест: две invoice, созданные параллельно, получают разные последовательные номера.

9. **Оформить git-историю как учебный проект**  
Каждый коммит — один законченный шаг, понятные conventional commit messages, без смешивания unrelated-изменений.
